二、核心算法口径（双轨设计）

这是本插件的技术核心，也是相对对标产品的差异化优势。

A轨道一：真实 IOPV（精确值）

适用：有 IOPV 的品种（全部 ETF + 部分 LOF，判据 has_iopv=Y / 腾讯 [78] 非空）

IOPV溢价率 = (现价 − IOPV) ÷ IOPV
　─ 现价：腾讯 [3]
　─ IOPV：腾讯 [78]（15秒刷新）
　─ 校验值：腾讯 [77]
  • 交易所官方发布，零估算误差
  • 无需跟踪比，无需汇率假设
  • 覆盖全部 ETF 与流动性好的 LOF

B轨道二：跟踪比估算（拟合值）

适用：无 IOPV 的 QDII（净值 T-2 滞后，判据 has_iopv=N）

估算净值 = 最新净值 × (1 + 参考涨幅 × 跟踪比)
　　　　　　× (1 + 汇率变动) 　[可选]
估算溢价率 = (现价 − 估算净值) ÷ 估算净值
  • 参考涨幅取 ref_increase_rt（集思录已算好）
  • 跟踪比默认 1.0，UI 可调（0.5~1.5）
  • QDII 汇率变动可从 cal_tips 解析

🔁 双轨自动路由逻辑

// 每行的溢价率取值决策
if (hasIopv && tencentField78 非空) {
    premium = (price - iopv) / iopv;        // 轨道A：真值，标记 ●
    source  = 'IOPV';
} else {
    estNav  = nav * (1 + refIncreaseRt * trackRatio);
    premium = (price - estNav) / estNav;    // 轨道B：估算，标记 ○
    source  = 'EST';
}
诚实标注原则：UI 上用不同标记区分「真值 ●」与「估算 ○」，鼠标悬停显示计算过程（净值日期、参考涨幅、跟踪比、是否含汇率）。TD-2 滞后的估算值本质仍是推测，不做过度承诺。

可复用的既有资产（来自转债插件踩坑经验）：
  • 插列铁律：表头/表体是两个独立 table，必须「两个 colgroup 各插 col + 同步加宽 table.style.width + 新节点 append 到行尾」三件套，中间插会被 Vue diff 冲掉。
  • gutter 列陷阱：表头 colgroup 末尾有 width=0 的滚动条占位 col，插 col 需 insertBefore(gutter)，否则整体错位一列。
  • guard 禁用「存在即跳过」：必须「先删全部 data-jisilu-* 节点 → 再完整重追加」。
  • 自愈守护：三不变量（注入 th 数 / col 数 / 两表 width 差 = 0）+ MutationObserver + 兜底 setInterval。
  • Extension context invalidated 防护：调 chrome API 前判 chrome.runtime.id。

五、风险清单与对策

按严重度排序，均为可缓解项，无阻断性风险。

→ 对策：选择器兼容两套 + 三不变量自愈 + 失败时优雅降级（只隐藏新列，不破坏原表格）。

→ 对策：DOM 为主（登录后页面渲染全量行），接口仅作字段补充。若用户未登录，显式提示「登录后可扫描全市场」。

中
QDII 估算精度受 T-2 滞后与汇率影响

海外基金净值 T-2，参考涨幅为 T-1，叠加汇率波动，估算溢价存在真实偏差。

→ 对策：UI 明确区分「真值 ● / 估算 ○」；悬停展示净值日期与计算过程；跟踪比可调让用户自行校准；纳入汇率修正项。

第三方非官方接口，字段位置可能变动；GBK 编码需处理。

→ 对策：字段位置采用「尾部锚点定位」而非硬编码下标（以 ~CNY~ 为锚向前定位），并写单测锁定；东财 push2 作兜底通道。
